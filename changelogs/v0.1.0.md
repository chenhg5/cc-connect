# cc-connect-next v0.1.0

The first stable release. Code-identical to `v0.1.0-beta.3`; this tag promotes the beta line and moves the npm `latest` channel onto it.

代码与 `v0.1.0-beta.3` 完全一致，本次只是把 Beta 线晋级为正式稳定版，并把 npm `latest` 频道移到它上面。

## 中文

cc-connect-next 是官方 [CC Connect](https://github.com/chenhg5/cc-connect) v1.4.1 的隐私优先继任者：独立的命令、数据目录、daemon 与 npm 包，不需要给官方打补丁，也不依赖 MCP、代理、伴生插件或消息快照。

### 这个稳定版包含什么

- **原生飞书 Card 2.0 回答卡片**：一个回合一张引用卡片，立即给出非空反馈，过程只显示匿名的「推理 N 次 · 工具 N 次」，答案在同一张卡片里流式呈现，最后落到 `✅ 已完成` 或错误态。推理文本、工具名称/参数/结果、模型、token、上下文、工作目录和 footer 都不进入卡片，也没有可展开详情。
- **一条命令的 fail-closed 迁移**：读取官方 `config.toml`、实际生效的 `data_dir` 和项目内 `.cc-connect`，全程 SHA-256 校验、原子启用、失败可回滚，产出 `migration-manifest.json`，并列出「迁移解决不了、需要人来改」的三类报告。兼容矩阵覆盖官方 v1.4.1 与 v1.5.0-beta.1 至 beta.3；不支持的字段在写入前失败，而不是被悄悄丢掉。
- **对齐分叉点之后的上游飞书能力**：话题级工作区绑定、已有话题首次 @ 的根上下文补入、带隐私门禁的引用文件下载、话题内 relay 可见性、显式 `mention_map`，以及按群免 @ 的 `group_reply_all_chats`。
- **默认即安静**：过程消息四件套默认关闭、完成时贴 `Done` 表情、界面默认中文；`mode` 显式写出时仍沿用官方语义。
- **装得上也说得清**：首次运行生成的配置由推荐飞书预设渲染，占位值没替换完就拒绝启动并指出下一步；`cc-connect-next doctor` 在不建立任何连接的前提下体检配置、Agent、平台、依赖与网络；平台连不上时启动 30 秒后明确报出来。
- **可校验的分发**：六个平台归档与 npm 包出自同一个 tag，安装脚本先验 SHA-256 再替换二进制。

### 仍然是外部门禁的事

真机飞书租户的渲染、权限、引用文件 API 与机器人间事件投递属于发布外验证，仓库测试无法覆盖，状态仍为 **UNVERIFIED**。官方 CC Connect 上游在本 tag 之后还有未审计的提交（Kimi 原生 dialect、pi 系列修复、若干新平台）。

### 安装与升级

```bash
npm install -g cc-connect-next
cc-connect-next --version
cc-connect-next doctor
```

从任何 `v0.1.0-beta.*` 升级都是就地升级，行为不变。官方 CC Connect 的二进制、配置目录、daemon 和飞书连接不受影响。

## English

cc-connect-next is a privacy-first successor to official [CC Connect](https://github.com/chenhg5/cc-connect) v1.4.1, with its own command, data directory, daemon, and npm package. No upstream patch, MCP server, proxy, companion plugin, or message snapshot is required.

### What this stable release contains

- **A native Feishu Card 2.0 answer card.** One quoted card per agent turn: immediate non-empty feedback, anonymous `reasoning N · tools N` progress only, the answer streamed into the same card, and an explicit `✅ Done` or error end state. Reasoning text, tool names/arguments/results, model, token, context, work directory, and footers never enter the payload, and there is no expandable panel.
- **A fail-closed one-command migration.** It reads the official `config.toml`, the effective `data_dir`, and project-local `.cc-connect` directories, hashes every source, activates atomically, rolls back recoverably, writes `migration-manifest.json`, and reports the three classes of thing a byte-faithful copy cannot resolve on its own. The matrix covers official v1.4.1 and v1.5.0-beta.1 through beta.3; unsupported settings fail before any target write instead of being silently dropped.
- **The upstream Feishu work merged after the fork point**, re-adapted rather than merged wholesale: topic-scoped workspace bindings, first-mention topic context bootstrap, privacy-gated quoted-file retrieval, topic-local relay visibility, explicit `mention_map`, and per-chat `group_reply_all_chats`.
- **Quiet by default**: process messages off, a `Done` reaction on completion, Chinese UI by default, with official `mode` semantics preserved whenever `mode` is spelled out.
- **An install that explains itself**: the first-run config is rendered from the recommended Feishu profile, startup refuses while placeholders remain and says what replaces them, `cc-connect-next doctor` checks config, agent, platforms, dependencies, and network without opening a connection, and a platform that cannot connect is reported 30 seconds after start.
- **Verifiable distribution**: six platform archives and the npm package come from one tag, and the installer verifies SHA-256 before replacing the binary.

### Still an external gate

Real Feishu tenant rendering, permissions, quoted-file API access, and bot-to-bot event delivery cannot be covered by repository tests and remain **UNVERIFIED**. Upstream CC Connect also carries commits this tag has not audited (native Kimi dialect, the pi fixes, several new platforms).

### Install and upgrade

```bash
npm install -g cc-connect-next
cc-connect-next --version
cc-connect-next doctor
```

Any `v0.1.0-beta.*` installation upgrades in place with no behavior change. The official CC Connect binary, data directory, daemon, and Feishu connection are unaffected.
