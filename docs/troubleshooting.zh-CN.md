# 故障排查

先确认执行的是本分支的新二进制，再检查 `cc-connect daemon status` 和 `cc-connect daemon logs -n 100`。日志查看命令结束只关闭查看进程，不停止机器人。Windows 数据默认位于 `%USERPROFILE%\.cc-connect`；实际路径以 daemon 元数据为准。

## 插件启动弹出控制台

**现象**：启动 Codex 或工具执行时出现 CMD/PowerShell 窗口，有时长期保留。

**修复**：本轮增加 GUI 子系统的 `cc-connect-plugin.exe`，MCP 通过它调用主程序的 `codex-plugin` 入口；Codex app-server、其他后台 Codex 调用及 taskkill 设置 `CREATE_NO_WINDOW` 和 `HideWindow`。普通 CLI 不修改控制台行为。

**诊断**：确认两个 EXE 位于同一目录，插件 `.mcp.json` 指向启动器且没有多余 `codex-plugin` 参数。Codex 使用插件缓存，修改源码目录的定义后须重新加载已安装插件。检查弹窗进程的路径、父进程和命令行；其他插件的 CMD 进程须分别处理。

**回退**：停止本插件后台，恢复已备份程序及 MCP 定义，再重新加载插件。恢复旧主程序时也恢复与其配套的定义。不要终止所有 `cmd.exe`、`codex.exe` 或 Codex 桌面进程。

**Windows Terminal 留在任务栏**：`powershell.exe -WindowStyle Hidden` 和 `Start-Process -WindowStyle Hidden` 仍会创建控制台，默认终端可能留下最小化窗口。任务计划现使用 `cc-connect-plugin.exe --supervisor <脚本路径>`，由 GUI 启动器以 `CREATE_NO_WINDOW` 创建 PowerShell；脚本以 `UseShellExecute = false`、`CreateNoWindow = true` 创建后台。更新主程序时也更新配套启动器，并重新安装任务动作；只换 MCP 定义不能修复旧任务计划。

**执行工具时闪窗**：旧 UTF-8 包装程序在 detached 进程中调用 `AllocConsole`，随后隐藏窗口，存在窗口先出现的间隙。新包装程序创建无窗口工作进程，再设置代码页 65001；中文输出和退出码保持原行为。也需更新已安装的 `utf8-shell/pwsh.exe`。

## 空闲时控制台闪现，守护状态与后台进程不一致

**诊断**：查看 `Get-ScheduledTaskInfo -TaskName cc-connect` 的 LastRunTime / LastTaskResult，再对比后台进程的启动时间。退出码 1、任务重复启动、原后台仍在运行时，应先检查守护错误；也需按父进程区分 Codex 其他插件和编码包装程序。

**已修复**：原守护脚本使用 `AppendAllText`，与持续打开日志的后台存在 Windows 文件共享冲突，写日志会抛出异常。现改为允许读写共享的追加流，并用真实打开的后台日志测试验证。此修复针对守护异常退出；仅凭控制台进程存在不能确认窗口可见。

**应用与回退**：备份守护脚本，保留 UTF-8 PATH，再更新脚本并于任务空闲时重启。若旧后台已脱离守护，只能在确认路径、命令行及启动时间后清理该后台进程树；不要终止 MCP 桥、Codex 桌面或其他插件。失败时恢复备份脚本再启动。

## 中文工具输出乱码

**现象**：正文中文正常，PowerShell 工具结果中的路径或文件名变为 `�`。

**状态**：此前已修复 Windows 子进程输出编码问题，本轮保留修复。见 [UTF-8 包装程序](../tools/windows-utf8-shell/README.md)。这是执行输出编码问题，不能用卡片替换字符恢复已丢失的信息。

**诊断**：在 daemon 实际启动环境中检查 UTF-8 包装程序目录位于 PATH 前方，确认调用的是配套包装程序。仅设置模型提示或修改主机终端编码不能替代进程环境修复。用只读任务输出当前路径、中文条目，检查新结果。

**回退**：恢复安装脚本生成的 daemon/包装程序备份；重新启动后台。旧卡片不会自动修复。

## 英文命令仍收到中文模板

**状态**：本轮修复。默认 `language = "auto"`，原始命令决定语言，参数和引用不参与命令语言判断；自动检测不再保存固定语言。

**诊断**：检查全局和项目的 `language`，固定项目语言会覆盖全局。发送 `/语言 auto` 后交替发送 `/帮助` 和 `/help`。`/help D:/中文目录` 应使用英文；手动 `/lang zh` 后英文输入仍使用中文，这是固定模式。旧卡片按钮使用所属卡片的语言元数据。

**回退**：显式设置 `language = "zh"` 或 `"en"` 可暂时固定模板；恢复自动用 `auto`。更换程序时先保存配置。

## thread-store conflict / active writer

**现象**：Codex 提示某个 thread 已有 active writer，无法 resume。

**限制**：桌面和机器人仍使用独立执行进程。桌面 stdio 未开放共享控制入口，本轮不修改桌面端，也不绕过互斥。

**处理**：保留已有上下文，复制独立机器人会话，或在确认原执行完成后释放原 writer。不要在桌面和机器人中同时恢复同一个可写 thread；仅查看执行记录不等于获得共享执行控制能力。

## 删除卡片一直显示“正在删除会话”

**诊断**：检查后台日志是否已出现删除成功/失败、是否卡在模型会话扫描，以及卡片刷新是否失败。区分“操作仍未结束”和“操作结束但旧卡片未刷新”。检查目标会话是否仍在执行，保留原日志再尝试更新后的会话列表。

**状态**：此前已有删除进度、结果与错误反馈逻辑，本轮只增加语言传递，不新增删除算法。不能仅凭卡片停留断言磁盘删除成功或失败。

**回退**：待执行空闲后重启后台，再刷新列表确认真实状态。不要重复批量删除未知状态的会话，也不要手工清空 Codex 会话目录。

## 额度行缺失或重置后暂时消失

**行为**：Codex 当前会话优先读取 `account/rateLimits/read` 或更新通知；查询最多等待 1.5 秒，原始数据缓存 30 秒。缺失百分比、未知窗口长度、超时、已过重置时间的旧窗口不显示。上下文、模型与额度各自独立。

**诊断**：用 `/usage` 检查登录账号的额度来源；确认当前是支持返回额度的登录方式，检查网络和日志中的接口错误。自带 API Provider 可能不提供 ChatGPT 五小时/周额度，缺失不会显示为 0%。重置时间按运行主机时区显示。

**回退**：网络恢复后下一次有效查询会恢复额度。无需删除登录凭证或重新创建会话。可关闭 `show_context_indicator` 暂时隐藏指标，保留 `reply_footer`、`show_workdir_indicator` 原有控制方式。

## 上下文用量多轮看似相同

上下文取最新请求统计，紧凑 Token 数保留一位小数，百分比取整数。连续短请求可能只增加十几个 Token，例如 127,356 和 127,369 都显示 `127.4k`，容量为 258,400 时均显示 49%。先对比当前机器人线程 rollout 的最新 `token_count.info.last_token_usage` 和时间戳，不能仅凭卡片数字相同断言数据未更新。不要把累计请求 Token 当成当前上下文，也不要为了让数字变化而添加估算值。

## 验证与 Windows 全量测试

Windows 上部分原有测试依赖 Unix Shell、路径与 HOME 行为，另有时钟敏感用例；全量失败不能直接视为本轮回归。先跑本轮专项、核心 CUJ 和 Windows CI，再核对同一提交的 Linux 完整 CI。原始测试日志留在本机，不把私人运行日志上传到仓库。
