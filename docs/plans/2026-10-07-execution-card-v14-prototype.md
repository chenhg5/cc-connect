## 展示与回复位置

用户发来一条消息后，管理者普通引用回复该消息，执行卡内按时间呈现公开说明和命令摘要；不默认新建话题。本文“思考内容”指已经公开给用户的说明、计划和进度摘要，不包含未公开的内部推理。

管理者派工、成员交付仍在群里真实 @ 对应接收 Bot；接收方普通引用回复对应派工或交付消息展示执行过程。补充和授权请求属于原任务，不创建另一轮任务。

管理者保持依赖检查与验收职责：成员提交不等于验收通过，未就绪的后续任务不提前派发。同一成员串行、项目内上下文保留、结束本轮后群继续接收新指令等 v0.13 规则继续有效。

## 分卡原则：公开说明与命令作为整体

一段公开说明与其后关联的一组命令摘要构成一个完整执行段。例如“先核对回复逻辑”与随后两条查询命令应放在一起。同一卡可包含多个完整执行段，优先持续更新当前卡。

只有当前卡容纳不下后续内容时才续卡；不因新增一条命令、达到固定命令条数、时间间隔或自然阶段结束主动分卡。分界优先选择下一段公开说明的开头，相关命令随该段一并进入下一卡。

若同一段的命令持续增长导致当前卡超预算，优先将尚未封存的整段连同说明一起续入新卡；稳定记录标识保持不变，旧卡中的详情入口和阅读位置必须能正确关联。不能只把命令单独搬到缺少上下文的新卡。

同一整段连空白卡也容纳不下时，在原卡按需显示该段的说明和命令列表分页；说明摘要如需收起，必须有完整说明入口，完整命令与结果仍可从对应命令详情查看。所有原文持久保存，不硬切命令、不丢输出、不为了长结果连续发多张只有命令的卡。

卡片不重复显示“执行记录一、执行记录二”或类似分段编号标题；正文直接接着展示公开说明和关联命令，只保留必要的状态与查看入口。分段编号仅供内部关联，不占用卡片标题和页脚。所有续卡仍普通引用回复本轮同一触发消息，顺序可追溯。进行中的调用使用稳定内部标识关联，不能因同名命令、乱序返回或续卡更新到错误记录。

## 容量与详情

按所选飞书发送/更新 API 的实际字节与组件限制计算预算，统计完整序列化卡片的 UTF-8 字节、JSON 转义、标题、布局容器、嵌套文本、按钮及签名参数。预留实际需要的补充/授权控件空间，不另设过低的固定文本阈值。

摘要只带截断命令、状态、耗时和定位信息；默认整条命令可点击。命令编号只用于内部关联，不展示 CMD001 一类编号。状态、耗时和预览合并为同一文本内容，不为每个词拆组件。

点击某条命令后，同一卡切换到该命令详情：完整命令在前、执行结果在后，一个连续内容区，整体分页；不分命令/结果两个面板。只把当前页放入卡片，未查看的完整记录不预塞入隐藏组件，也不塞进按钮参数。

摘要页、详情页、等待补充页和等待授权页分别校验容量；分页不增加群消息。执行期间查看详情保留阅读快照和页码，新进度只提示，手动刷新或返回摘要时读取最新状态。群卡是共享视图。

## 补充与授权：操作留在原执行卡

需要用户补充时，原执行卡顶部展示等待状态、原问题、原选项及必要的文字输入；未提交草稿保留，空白输入不提交。回答绑定原请求，成功回传后继续同一任务。无关的群聊消息不自动当作回答。

需要用户授权时，在原卡展示操作、目标、影响与范围，仅提供执行端实际支持的授权选项。一次同意仅适用于所显示的范围；拒绝暂停对应操作，不能等超时后当作同意，也不能自行扩大权限。登录或平台 OAuth 使用实际授权流程，在私聊完成。

阅读详情时待处理提示仍可见，处理后保留阅读位置。服务端核验处理人、任务/轮次、请求有效性；回传失败要明确标示，不能提前显示已执行。旧按钮、重复提交和跨任务回答不得影响其他运行。

## 提醒走私聊

管理者向原始任务发起者或明确指定的处理人私聊提醒；成员提出问题时也保留该人类归属，不把派工 Bot 当成审批人。私聊只包含任务/群归属、待办摘要和“查看执行卡”链接，不复制命令、日志或授权按钮。

点击私聊入口回到群内对应原执行卡处理。每项待办只提醒一次，查看详情、卡片刷新、进度追加及发送重试不会重复提醒；处理完毕后历史提醒返回当前有效状态。

持久化待办状态、通知投递状态和幂等标识。通知失败时原卡如实显示未送达并允许安全重试，不自动改为群里 @。正式实现需验证私聊触达、消息链接与客户端通知表现，不能把发送成功等同于用户已经看到。

## 最终结果与历史查找

执行结束时原卡标记真实终态，群内另发一条普通引用回复交付最终结果，说明完成项、交付入口、验证结果及未解决事项。失败、部分完成、停止不得伪装成成功。

最终回复不重复整段日志；原执行卡与完整记录保留，查看详情时不强行切走。项目面板和历史任务索引保存任务、原指令、各段执行卡和最终结果之间的关联，便于找回记录。消息删除或更新过期时明确说明并提供现有可用入口，不编造链接。

## 分卡示例与评审路径

容量充足：同一张卡显示“说明 A → 命令 A1、A2 → 说明 B → 命令 B1”；追加“说明 C → 命令 C1”仍在同卡。容量不足：下一张卡从“说明 C”开始，后面紧跟命令 C1，仍回复原指令。

打开设计稿，先点“模拟新增进度”，确认说明和命令在同一卡追加；再点“模拟容量不足再续卡”，确认新卡以说明开头。点击命令检查合并详情和返回，切换私聊检查待处理提醒返回原卡。

设计稿采用固定模拟数据和演示分页；容量不足按钮只用于演示。真实容量计算、超大单段摘要分页、持久化记录、原生回调、私聊投递和历史索引已接入 cc-connect 源码并完成自动化验证；设计稿链接保持不变，实际飞书投递和客户端表现仍需上线后实点验收。

## 原型行为

- 每条记录有「完整命令」「执行结果」。点击后同一卡片切换到选中记录详情，支持标签切换、上一页/下一页、返回执行摘要。
- 摘要仅渲染短预览。正式实现应将完整记录持久化到服务端，按卡片字节和组件预算按需加载当前页；不能把全部日志预塞入折叠区。
- 阅读详情时保持输出快照，新进度只提示；可手动更新，返回摘要时呈现最新记录。
- 超容量时续发普通引用回复；旧段记录保留，新卡引用同一条触发消息。
- 群卡是共享视图。翻页会改变所有群成员看到的卡片；点击详情只读记录，不执行命令、派发任务或真实提及机器人。
- 四种场景：管理者处理、成员接单、管理者验收、长任务续卡。原型的 @ 均是模拟显示。
