# 执行卡与结论消息显示修复

## 用户可见行为

- 过程卡先展示公开进展和命令，当前动作在卡片底部显示：工具执行中、等待模型响应或正在整理回复；完成、停止和失败状态也放在底部。
- 普通经理回复不再自动 @ 发起人。成员接收任务、成员向经理提交结果仍保留结构化机器人 mention；原发起人身份仍保存，用于后续问题和审批。
- 任务和结论使用富文本消息的 `md` 节点呈现 Markdown。结构化 mention 单独占一行。接收消息和引用回复的解析同时支持 `md` 与 `markdown`，避免机器人交接丢失正文。
- 原生执行流等到公开内容、命令、问题或提示出现后才创建卡片。只有最终回答的问答直接交付结论，避免留下仅有“已完成”的过程卡。
- 若等待提示曾创建临时过程卡、结束时已无内容，则撤回本回合的空预览；不会批量删除历史卡片。
- 容量测量固定状态图标的预算，运行状态变成完成状态时保持详情页边界稳定。
- 命令只展示紧凑的摘要与执行状态，取消整行详情跳转、蓝色链接样式和“点击命令查看详情”提示。超长正文的展开、审批与问题操作继续保留；旧卡片的详情回调仍兼容。

## 验证

- 新增状态顺序、状态切换、空执行、纯结论、无人工 mention 的引用结论回归用例，修复前均失败。
- Markdown 结果的发送、机器人接收与引用读取回归用例，补齐解析前失败。
- 更新原有流程用例以验证机器人 mention 继续保留、人工 mention 移除后原发起人身份不丢失。
- `go test -tags agent_team ./...`、独立 CUJ 测试与相关包 `go vet`。

## 发布边界

修改针对 cc-connect 团队服务。部署前检查当前任务和各原生模型回合均已结束；不修改飞书账号权限、模型审批模式或 ADB 配置。已经发送的历史消息不批量重写。
